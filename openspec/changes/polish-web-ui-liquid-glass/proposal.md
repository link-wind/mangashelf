# Proposal: polish-web-ui-liquid-glass

## Why

当前前端已完成基础功能与移动端适配，视觉底子（B 站蓝系 `#00aeec`、暗色模式、沉浸式阅读器与自定义播放器）已成型，但在视觉精致度、页面风格一致性与交互细节上存在明显断层：

1. **浮层与媒体视觉层次不足**：顶栏、Hero Banner 控件、阅读器/播放器浮层、移动端菜单及登录页仍停留在普通半透明或纯色底，缺乏与动漫/漫画高饱和彩图呼应的通透质感。
2. **早期页面与新版页面风格割裂**：`Shelf.tsx`（我的收藏）、`Login.tsx`（登录页）、`Search.tsx`（搜索页）仍沿用早期布局与样式，与首页和索引页的 `3:4` 卡片体系不一致；`Search.tsx` 还缺少外部漫画目录结果展示且存在目录错误被静默吞掉的问题。
3. **若干影响体验的细节缺陷**：
   - 暗色模式在 React `useEffect` 中设置 `data-theme`，刷新时会出现短暂白屏闪烁；
   - 手机端（≤720px）隐藏了顶栏搜索框，但悬浮菜单漏掉了搜索入口，且顶栏与菜单内重复出现设置/退出/主题按钮；
   - 封面图加载失败后直接隐藏 `<img>`，在部分卡片变成纯灰块；首页「继续阅读」缺少封面与可视化进度条；
   - 首页首屏加载无骨架屏，收藏/取消收藏等操作缺少轻量反馈（Toast）；缺少站点 Favicon 与路由级动态标题；
   - 零散使用 Unicode 字符（`◐`/`☰`/`✕`/`→`）充当图标，且 `styles.css` 单文件超过千行并残留废弃样式。

对应设计依据：`docs/DESIGN.md` 第 4 节（页面与主要交互）及既有 `openspec/specs/web-ui/spec.md`。

## What Changes

本次变更聚焦前端视觉与交互升级，**不改动后端业务模型与数据库结构**：

1. **建立克制的“液态玻璃（Liquid Glass）”浮层材质体系**：
   - 严格遵循“浮层玻璃、正文实体”原则：仅作用于悬浮顶栏、Hero 悬浮控件/缩略图托盘、阅读器/播放器浮动控制条与目录抽屉、手机端悬浮球与弹出菜单、用户头像下拉菜单、Toast 与登录页玻璃卡；列表卡片与表单保持实底以确保滚动流畅与可读性。
   - 明暗双主题独立调校玻璃面渐变、高饱和模糊（`backdrop-filter`）、高光内描边与投影，并兼容 `prefers-reduced-motion` / `prefers-reduced-transparency` 降级。
2. **顶栏与移动端导航收口**：
   - 桌面顶栏将 `用户名 / 我的素材 / 设置 / 退出` 收进玻璃下拉头像菜单，缓解 1280px 下的拥挤；
   - 手机端（≤720px）补齐悬浮菜单内的「搜索」入口，并消除顶栏与悬浮菜单的按钮重复；
   - 使用统一风格的轻量内联线性 SVG 图标替换散落 Unicode 字符。
3. **体验基础设施补齐**：
   - 在 `index.html` `<head>` 内前置主题初始化脚本（支持跟随系统与记忆），消除暗色刷新白屏闪烁；补充站点 SVG Favicon 与路由动态 `document.title`；
   - 新增统一 `<CoverImage>` 组件（渐变首字兜底 + 加载淡入）与全局轻提示 `<Toast>`；
   - 首页增加首屏骨架屏、Hero 淡入淡出切换与响应式高度适配、卡片 hover 微动效及「继续观看/继续阅读」底部细进度条。
4. **早期页面视觉统一与搜索体验修补**：
   - 重构 `Shelf.tsx` 复用全站 `3:4` `.work-card` 视觉体系；
   - 美化 `Login.tsx` 为柔光渐变背景 + 液态玻璃登录卡（含密码显隐与提交态）；
   - 优化 `Search.tsx` 为来源分区视图（含外部漫画目录），移除静默 `.catch`，修复“有番剧命中却显示无结果”的空态误判；
   - 清理 `styles.css` 废弃的旧版 `.banner` 样式并拆分基础样式模块，美化暗色滚动条。

## Capabilities

### New Capabilities

（无新增独立业务能力，所有 UI 要求归入既有 `web-ui` 规格。）

### Modified Capabilities

- `web-ui`：补充移动端搜索入口与不重复按钮要求，新增液态玻璃浮层材质规范、暗色主题无闪烁初始化、统一封面兜底与全局操作反馈、以及首页/收藏/登录/搜索页的一致性交互要求。

## Impact

- **受影响目录**：仅 `web/`（`index.html`、`src/App.tsx`、`src/styles/` 或 `src/styles.css`、`src/components/`、`src/pages/Home.tsx`、`Shelf.tsx`、`Login.tsx`、`Search.tsx`、`ExternalMangaReader.tsx`、`Reader.tsx`）。
- **依赖影响**：优先使用轻量内联 SVG 组件，不新增重型 UI 组件库，保持 Vite 构建体积克制。
- **兼容性**：后端 API 接口零破坏；不支持 `backdrop-filter` 的浏览器自动回退为高不透明度纯色浮层。

## 追加（2026-11-25）：访客浏览公开内容

原提案声明「不改动后端业务模型」，本轮一并补齐 DESIGN 3.1/3.2 的访客浏览能力，因此**新增后端安全层的只读放行与认证语义调整**（不改数据表结构）：

- 新增 `@OptionalAuthUser` 解析器（未登录注入 `CurrentUser.GUEST` 全零主体），公开只读端点不再强制登录；数据层既有 `owner_id = viewerId OR is_public` 过滤天然把访客限制在 `PUBLIC+PUBLISHED`。
- `SecurityConfig` 放行公开读端点；认证入口返回 401 JSON、授权拒绝返回 403 JSON（细化 DESIGN 16.2）。
- 前端公开路由始终可进、私有路由 `RequireAuth` 引导登录；访客进度/收藏不提交。
- 一并修复：`/actuator/health/**` 放行（readiness）、封面 404 兜底确认、测试数据清理脚本。

后端影响限于身份/安全层与少量 Controller 注解，业务服务与数据库迁移无变更。
