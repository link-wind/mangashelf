# 提案：可用性闭环与内容厚度（M10/M11/M12）

## 背景

M9 之后站点具备「本季新番 + 7506 部目录 + 站内播放」，但盘点出四类缺口：
站内搜索不覆盖番剧目录、同步全靠手动、外部集进度只存 localStorage、目录/作品
详情页信息薄。另有工程欠账（OpenSpec 未归档、零单测）。

## 变更内容

### M10 可用性闭环

1. 搜索页并行检索番剧目录（`/catalog-items?q=`），目录结果以封面卡展示。
2. 周期同步：worker 角色每 30 分钟按需触发目录增量同步、每 6 小时触发 Bangumi
   日历；事实仍落 jobs 表（`ScheduledSyncService`）。
3. 外部集观看进度服务端化（V11 `external_watch_progress`，按 user+work+ordinal
   记录，切线路不丢），新增观看历史页与首页「继续观看」。
4. 解析限流：每用户 20 次/分钟，防止公开部署被当作免费解析接口。

### M11 内容厚度与容错

5. 多线路（V11 `line_name/line_rank`）：物化写入全部线路，观看页可切换线路，
   同集号映射保证进度连续；正片/PV·特典分组（`episode_type`）。
6. 目录条目详情页（封面/Bangumi 简介/线路概览/加入书库）。
7. 作品详情页封面化：封面 + Bangumi 评分/放送星期/简介 + 线路名。
8. 规则源 Cookie：登录墙源的 Cookie 仅服务端持有，随解析任务下发。

### M12 体验与纪律

9. 暗色主题（`data-theme` 驱动 CSS 变量，localStorage 记忆）。
10. OpenSpec 历史变更全部归档（M0–M5）。
11. 首个单元测试：标题归一化与相似度（真实样例固定行为）。

## 不做/延后

- 弹幕（弹弹play）：需要新增外部依赖与协议兼容评估，延后单独提案。
- 追番更新红点：依赖目录集数变化检测，随 M13 一起做。
- 单集失败自动换线路：当前提供手动切线路 + 重新解析，自动换线需失败原因分类，延后。
