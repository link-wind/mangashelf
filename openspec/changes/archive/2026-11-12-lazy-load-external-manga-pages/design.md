## Context

见 proposal.md。DESIGN §14.1 要求不一次请求整章原图，§19 保持受限代理和登录边界。
腾讯规则和 MangaDex 已通过 HTTP 取清单；拷贝、包子和嗨皮现有路径使用浏览器取地址，
不是截图。除哔哩外，清单通常只有 URL，没有每页尺寸；图片可能不允许跨域 fetch。

## Goals / Non-Goals

**Goals:** 所有外部源均明确限制取图范围；条漫续读不预读章首；未知尺寸更新不改变阅读
锚点；保留单页、双页、高清、方向及历史行为。

**Non-Goals:** 不在本轮逆向所有上游，不复用哔哩专用匿名参数，不保存其他源的个人
登录态或临时签名。此轮前端范围不扩展为通用服务端图片缓存框架。

## Decisions

- 将哔哩页组件扩为外部源共用的页组件。哔哩保留同源 fetch、JSON 错误及取消；
  其他图片用原生 img 请求，继续使用浏览器 HTTP 缓存，不因跨域 fetch 限制破坏直连。
  直连失败只尝试一次既有白名单代理，最终失败展示重试，不再隐藏页面。
- 按视口观察，进度恢复前不赋正文地址；双页只挂当前页组并预取下一组。去掉独立的
  章首探测请求，用清单尺寸或实际阅读中已加载的图片判断条漫，保持用户手动模式优先。
- 清单状态与来源、章节一同保存，路由切换后仅使用归属匹配的清单，等待新章时不展示
  或重挂旧页图。
- 优先清单尺寸，其次本机最近章节记录的实际尺寸，再使用估计占位。本机尺寸缓存只存
  数字，不存 URL 或 Cookie，按来源、章节区分并限制最近章节数；清晰度切换共用
  长宽比占位，实际加载后更新尺寸。
- 未知尺寸更新前记录当前页相对视口的位置，布局更新后修正滚动，防止前一页变高把
  当前页推走；条漫自动切滚动时保持当前页。估计尺寸不宣称精确总滚动高度。
- 验证使用实际生产构建与受控的长条图/失败样本记录服务器收到的图片请求，补真实
  腾讯与哔哩样本；受控 UI 不用于声称其他源的 HTTP 提取已成功。

## Risks / Trade-offs

- 未加载图片尺寸未知 → 占位、已知尺寸缓存与锚点修正，不提前下载整章测尺寸。
- 上游不允许直连或代理 → 明确页级失败与重试，保持原代理白名单，不放宽任意 URL。
- 无权访问的浏览器源 → 保留清晰错误；未验证纯 HTTP 的来源不声称已脱离浏览器。

## Migration Plan

部署 Web 即生效，不迁移数据库或旧页图。回滚 Web 可恢复旧呈现；尺寸缓存独立于
阅读进度及认证，不存正文，可以在回滚后自然忽略。

## 2026-11-12 实现与实测

- 共用页组件已覆盖全部外部源；哔哩保留同源 fetch，其余原生 img 保留 CDN HTTP
  缓存与既有白名单代理。没有放宽代理域名或变更服务端会话。
- 80 页生成条漫首轮只请求第 1 页；直接跳末页时只增加末页请求。第 40 页冷续读及
  自动、手动模式切换均保持第 40 页，附近请求 39–42，未请求章首。
- 受控验证发现相同原生 img 地址重试未产生新请求，已改为先移除失败元素，再重新
  设置地址；直连/代理失败及同源 JSON 错误两条路径均复验成功。
- 484×827 的当前内置浏览器窗口无横向溢出。真实腾讯第 11 页、哔哩第 20 页解码通过，
  Web 构建与 Docker 静态产物比对通过。详见
  `docs/validation/external-manga-lazy-loading.md`。
- 浏览器源的服务端解析仍可能由源站触发图片请求。本轮只统一阅读端按需加载，不声称
  拷贝、包子、嗨皮的章节索引已完成纯 HTTP 替换。
- 最终复核补上清单归属绑定；站内下一话在延迟清单期间显示解析中，恢复后仍在第 40 页，
  仅请求 39、40、41 页，且逐话进度门禁均通过；重新构建并更新 Docker Web。
