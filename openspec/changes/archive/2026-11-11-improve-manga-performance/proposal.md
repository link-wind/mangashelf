# 提案：漫画首页/切换/阅读性能优化（M34）

## Why

用户反馈漫画首页、切换数据源、阅读都偏慢/卡。定位到四类问题：
1. 首页聚合每次冷启动要等各源抓取（含哔哩跨源桥接 ~10s）；
2. 切换源重复请求，且前端清空内容导致白屏；
3. 浏览器源每次解析都起新浏览器 + 固定滚动等待；
4. 长章节滚动时每帧遍历所有图片计算页码。

## What Changes

1. 服务端分区缓存 `MangaSectionsService`（10 分钟），聚合与 `/sections` 共用；
2. API 启动后台预热聚合推荐（4s 左右），首页首开不再冷等；
3. 浏览器解析结果双层缓存（内存 + 磁盘），重启后仍命中；
4. Python 解析：页图可一次取全时跳过滚动；goto 后等待 load + URL 稳定；
   镜像页空壳自动重载重试；
5. 前端首页分区 localStorage 缓存 10 分钟，切换源先渲染缓存再后台刷新；
6. 阅读器滚动页码计算改为缓存图片列表 + 100ms 节流。

## 不做

- 不做浏览器进程常驻复用（任务模型不变）；
- 不改变各源数据抓取策略，仅缓存与等待优化。
