## Why

纯 HTTP 验证已在两个匿名公开章节通过完整取图，现有逐页浏览器截图、上传对象和轮询仍占用大量资源。依据 DESIGN §12、§14、§18–§21，改为服务端 HTTP 获取索引、读到时下载图片并持久缓存，保持目录、权限和历史续读。

## What Changes

- 哔哩详情、章节索引和页图改为 HTTP，不再启动浏览器采集或执行截图轮询。
- 章节返回完整页序及同源站内页图地址；阅读器按可见页加载，显示页级加载状态和可重试错误。
- 服务端保存有期限的目录、索引和已下载原图；相同页并发合并，缓存跨重启复用，受过期与容量上限约束。
- 原站锁定、参数非法、图片损坏和网络失败明确报错；签名地址与匿名指纹不落日志或磁盘。
- 以真实本地及 Docker 链路验证冷启动、末页、历史续读、缓存与权限。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `manga-sources`：哔哩完整阅读改为完整索引加按需页图，缓存重启复用，页级错误不伪装加载成功。

## Impact

涉及 Java 哔哩 HTTP 与缓存、统一页图入口、阅读器加载逻辑、Compose 持久卷和验证文档；移除服务端 canvas 会话入口。保留其他浏览器漫画源，不新增表、队列或通用缓存框架。
