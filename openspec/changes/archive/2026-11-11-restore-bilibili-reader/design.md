## Context

M35 已有浏览器页图任务和同源读图路由。解析由 API 同步调用固定 Python 入口，默认部署却缺少该运行时。设计依据为 DESIGN §3.3、§4、§12.2、§18–21。

## Goals / Non-Goals

- 用一个匿名可读的真实哔哩章节验证页序、末页和历史续读；用可重复的缺页输入验证明确错误。
- 第一阶段不改首页路由。第二阶段只在公开页面能可靠提供章节列表时接回站内；不猜测章节 ID，不规避上游登录和付费限制。
- 不引入通用任务框架或新增数据库表。

## Decisions

- 第一阶段保留现有解析入口，在 API 镜像加入浏览器任务所需的最小运行时，修复 Worker 的 Python 包路径；浏览器代理由部署显式配置，留空则直连。Python 子进程使用受限环境和实际生效的超时。
- 捕获任务先确认上游页数，再按页位采集已渲染的页面；对缺页、未知页数或异常页位返回明确错误。服务端校验连续页序和产物后才返回完整清单，临时目录在失败时也清理。
- 截图仅来自匿名公开页面，仍要求站内登录，读写使用同一配置桶；每次采集生成独立对象路径，避免覆盖旧页图。响应不得进入共享缓存。
- 历史链接保留来源和章节 ID，从服务端进度恢复；第二阶段依赖真实公开作品页的章节清单证据，失败时保留原站入口。

## Risks / Trade-offs

- 上游网络和阅读器结构会变 → 限时失败并记录诊断，避免把部分页标成成功。
- 浏览器启动成本和对象留存仍需控制 → 保留当前小并发和缓存机制；本次验收仅对隔离环境，记录对象保留限制。

## Migration Plan

隔离 Compose 项目使用空库、独立端口与私有桶重建镜像，保留现有开发环境。无 Flyway 迁移。历史截图使用的旧路径可以失效，重新解析后返回当前清单。

## 2026-11-11 实测补记

- 哔哩桌面并页模式会随阅读方向改变键盘翻页行为，边界处可切换章节。改用原站进度条和页位 HUD，分别按主、副画布的页号采集。滚动模式则按页面顺序等待原站的渲染完成标记。
- 固定 Python 入口原先在启动时导入 OCR。改为只在 OCR 任务使用时导入，让 API 镜像只带浏览器依赖。隔离全栈的漫画解析和 Worker 的 CBZ 解析均能执行。
- 受控样本完成采集、读图、翻页、历史续读；真实《航海王》第 004 话只确认了 2/20 页，仍须完成真实章节验收。详见 [M35 验证记录](../../../docs/validation/m35.md)。第二阶段尚未开始。

## 2026-11-11 真实章节再验

- 第 3 页实际有图，原实现以页组为单位确认，才报告 2/20。第 4 页起原站使用另一套加密页图加载器，旧运行环境中它在发出图片请求前返回错误。普通 Chromium 在匿名会话中能正常渲染末页。
- 哔哩任务改用独立的普通 Chromium 进程（Linux 以 Xvfb 提供显示环境），由本地连接负责翻页和截图。复用现有固定入口和受限进程环境。没有修改原站加载器，也不提取其令牌、签名或会话。
- 逐页确认并按编号暂存；先走完可定位的页组，再回补缺页，直到截止时间。只有页序完整才交付，缺页提示给出第一个缺失页。本地真实阅读及历史续读已通过。
- 目录由原站公开详情页正常加载，读取其用于章节控件的清单。清单长度必须等于原站声明的总数，章节 ID 必须有效且唯一；只把明确免费且未锁定的条目标记为站内可读。首页先进入站内目录，失败或锁定时保留原站链接。
