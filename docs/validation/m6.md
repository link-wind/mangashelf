## 2. 真实链路验证（本地 mock 站点）

规则引擎不是打桩验证，而是对本地起真实 HTTP 服务（python http.server）用规则
JSON 全链路请求：

### 2.1 HTML 模式（:18999 静态站点）

规则：`searchList=.item`、`searchName=.title`、`searchUrlSelector=a`、
`episodeListSelector=.ep-list a`。结果：

- 搜索关键词返回 3 条（浪客剑心 / 葬送的芙莉莲 / 其他作品）；
- 详情页解析出 3 集（第1话 序章 / 第2话 相遇 / 第3话 决意）；
- 相对路径 `/watch/yaiba/1` 基于 episodePageUrl 补全为
  `http://127.0.0.1:18999/watch/yaiba/1`；
- 解析结果原样提交绑定端点成功。

### 2.2 API 模式（:18998 JSON 端点）

规则：`searchMode=api`、`apiListPath=$['list'][*]`、`apiNamePath=$.name`、
`apiUrlPath=$.url`。结果：返回 2 条、URL 基于 baseUrl 补全 ✓。

## 3. 过程中修复的缺陷

| 缺陷 | 根因 | 修复 |
| --- | --- | --- |
| 创建规则源 500 | 冒烟/前端把 `rules` 作为 JSON 对象发送，Controller 声明为 String | Controller 改收 `JsonNode`，Service 层 `toString()` 入库；INSERT 加 `?::jsonb` 显式 cast |
| toggle 返回语义错误 | 返回值是"更新行数>0"而非新状态 | 更新 0 行抛 404；响应回显请求的新 enabled 值 |
| API 模式搜索 500 | `String.valueOf(JsonPath.read(...))` 被 javac 推断为 `valueOf(char[])` 重载（比 `valueOf(Object)` 更具体），生成 `checkcast [C` 字节码 | 显式 `Object v = JsonPath.read(...)` 阻断推断 |
| 冒烟打到旧容器 | M5 部署实测留下的 `--profile full` 容器占 8080，内为无 external 模块旧 jar | 停容器化 api/worker/web；本地验证前先确认 8080 归属 |

## 4. 已知限制

1. 规则引擎不执行 JS、不加载 WebView（方案 A 既定边界）：React/Vue 动态渲染的
   站点无法解析，仅适用服务端渲染 HTML 或 JSON API 站点。
2. 分集解析仅 HTML 模式（Kazumi 子集）；API 模式目前仅覆盖搜索，详情分集走
   HTML 解析。
3. 视频直链提取（m3u8/mp4 解析）未做——外部集以链接跳转（新窗口打开原站）方式
   播放，不代理视频流；版权边界与代理合法性留待后续决策（DESIGN 17.2 模式：
   来源 ID 回链，不落视频文件）。
4. 规则源导入无格式校验白名单（缺 searchList/episodeListSelector 在搜索/解析时
   才显式报错"规则缺少 …"）。
5. 外部站点请求超时 15s 固定，不可按规则源配置。

## 5. 前端入口

- **Settings 页（管理员）**：外部动画规则源管理——粘贴规则 JSON 导入、启停、删除。
- **作品详情页 → 外部动画源**：选源 → 关键词搜索 → 点击结果解析分集 → 勾选绑定；
  已绑定列表带"播放"（新窗口跳原站）与"解绑"。
