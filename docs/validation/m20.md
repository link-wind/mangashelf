# M20 验证记录：浏览态播放（不落库）

> 日期：2026-11-09 · 变更：implement-browse-playback（已归档）
> 结论：外部剧集可挂在「目录条目」上直接播放，浏览不再创建作品；
> 只有显式点「加入书库」才物化，并把已生成的剧集整体收编到作品下。

## 1. 为什么需要

原模型要求 `external_episodes.work_id NOT NULL`，导致「首页点开即播」必须先把目录条目
变成作品——纯浏览也会污染书库（实测一次点击产生 3 个作品）。

## 2. 数据模型（V14）

```sql
ALTER TABLE external_episodes ALTER COLUMN work_id DROP NOT NULL;
ALTER TABLE external_episodes ADD COLUMN catalog_item_id uuid REFERENCES external_catalog_items(id) ON DELETE CASCADE;
-- 唯一性改为两个部分索引；归属二选一
CREATE UNIQUE INDEX uq_ext_ep_work    ON external_episodes (work_id, source_id, line_name, ordinal)       WHERE work_id IS NOT NULL;
CREATE UNIQUE INDEX uq_ext_ep_catalog ON external_episodes (catalog_item_id, source_id, line_name, ordinal) WHERE catalog_item_id IS NOT NULL;
ALTER TABLE external_episodes ADD CONSTRAINT ext_ep_owner_check
    CHECK ((work_id IS NOT NULL)::int + (catalog_item_id IS NOT NULL)::int = 1);
```

## 3. 行为

| 动作 | 结果 |
| --- | --- |
| 首页/索引点卡片（未入库） | 进入 `/browse/{itemId}`，懒生成剧集（挂目录条目），**不建作品** |
| `/browse` 播放 | 复用 `external.resolve` 任务与解析缓存（剧集仍是 external_episodes 行） |
| 点「加入书库」 | 建作品 + `adoptEpisodes` 把浏览态剧集改挂作品（不重复解析） |
| 已入库条目 | 仍走 `/works/{id}` → 直达播放页 |

## 4. 实测

- 首页点「小星帽尼欧欧」→ 落在 `/browse/{item}/568e1466…`，界面显示「浏览模式（未加入书库）」
- 数据库 `works` 保持 **2**，浏览态剧集 96 条（48×2 线路）
- 解析：`POST /external-episodes/{id}/resolve` → SUCCEEDED，直链 m3u8
- 点「加入书库」→ 新作品 96 集、`catalog_item_id` 归零（收编成功）；随后清理脚本移除测试作品

## 5. 已知限制

1. 浏览态进度只存 localStorage，未进服务端观看历史（入库后才有服务端进度）。
2. 浏览态剧集按需生成（首次打开播放页多一次解析写入，毫秒级）。
3. 清理目录条目会级联删除其浏览态剧集（`ON DELETE CASCADE`）。
4. 未做「浏览态 → 入库」后的进度迁移。
