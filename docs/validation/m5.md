## 2. 部署（DESIGN 20.1）

### 2.1 容器镜像

| 镜像 | 基础 | 内容 |
| --- | --- | --- |
| server/Dockerfile | maven:3.9-eclipse-temurin-25 → temurin:25-jre-noble | API/Worker 同一 jar，角色经 MANGASHELF_ROLE |
| server/Dockerfile.worker | 同上 + python:3.14-slim 构建层 | OCR venv（RapidOCR 模型缓存烘焙）+ ffmpeg + processing/ |
| web/Dockerfile | node:25-alpine → nginx:alpine | vite 构建 + /api、/media 反代（deploy/nginx/nginx.conf） |

### 2.2 一键部署

```bash
docker compose --profile full up -d
```

- e5 模型文件（133MB）以只读卷挂载 `./server/models:/opt/models:ro`，不进镜像。
- compose `db`/`rabbitmq`/`storage` 保持默认 profile（开发共用）；api/worker/web 在
  full profile 下启动并依赖健康检查。
- nginx `/media` 转发保持签名 Host（`proxy_set_header Host storage:9000`）。

**实测**：三镜像全部构建成功并全栈启动通过——
- `mangashelf-api:latest` 888MB（eclipse-temurin:25-jre-noble + jar）
- `mangashelf-worker:latest` 2.39GB（venv 自含 Python 3.14 + RapidOCR 模型缓存烘焙 + ffmpeg + jar）
- `mangashelf-web:latest` 93.6MB（nginx + dist + 反代配置）

`docker compose --profile full up -d` 六服务全 UP；浏览器经 nginx :5173 访问站点、
API 经反代返回预期 403（CSRF/未认证）。Dockerfile 使用本机已构建 jar/dist
（CI/CD 流水线模式）；Worker 的 OCR venv 自含 Python 3.14 解释器 + 模型缓存烘焙
（运行期零联网，noble 的 apt 无 python3.14 故不能只装解释器——已修正为整体拷贝 venv）。

## 3. 可观测性（DESIGN 20.2 最小集）

- RequestObservabilityFilter：每请求生成 `request_id`（UUID）入 MDC + `X-Request-Id`
  响应头；认证后补 `user_id`。
- 日志 pattern：`%d %-5level [%X{request_id}] [%X{user_id}] %logger - %msg`
- 样本（异常日志带 request_id，可定位跨进程任务）：

```
2026-11-08T19:15:31.477+08:00 INFO  [req_99f7129d-25fb-4fcc-8415-c923bb136c35] [] o.s.a.r.c.CachingConnectionFactory - Attempting to connect to: [localhost:5672]
```

- `GET /actuator/prometheus` 返回 200，246 个指标族（JVM/HTTP/RabbitMQ 连接池/Hikari 连接池）。
- 关注指标（PromQL 名称）：`http_server_requests_seconds`（延迟分位）、
  `hikaricp_connections_active`（连接池）、`jvm_memory_used_bytes`（内存）。

## 4. 备份恢复演练（DESIGN 20.3）

### 步骤

1. `scripts/backup.sh` → `backups/<时间戳>/{db.dump, storage-data.tar.gz}`（294KB + 6.6MB）
2. `docker compose down -v`（全量销毁）
3. `docker compose up -d db storage rabbitmq`（空环境）
4. `scripts/restore.sh <备份目录>`：pg_restore + 数据卷 tar 回放
5. 启动 API → admin 登录 → 作品列表 5 个 ✓ → 页面签名图 GET 200 ✓

### 实证

- **"只备份数据库不能恢复漫画原图"**：db.dump 仅 294KB（索引数据），原图在
  storage-data.tar.gz（6.6MB）——两者缺一不可，20.3 的提醒在演练中实证。
- pg_restore 含 Flyway 历史表，应用启动不再重复迁移（版本一致性保住）。

## 5. 容量测量（DESIGN 21.3）

### 固定数据集

2 作品 × 12 页（800×1200 PNG 含中文文本）、1 批次索引（12 页 OCR + e5 嵌入）。

### 索引吞吐

| 项目 | 值 |
| --- | --- |
| 12 页端到端（下载→OCR→嵌入→上传→落库→激活） | 3177ms |
| 折合吞吐 | **3.8 页/秒**（含全部阶段） |

### 端点延迟（API 口径，curl time_total，N=50/50/30）

| 端点 | p50 | p95 |
| --- | --- | --- |
| 目录列表（20 条） | 6ms | 8ms |
| 页面窗口（5 页 + 预签名） | 11ms | 14ms |
| 搜索（字面+语义 RRF） | 15ms | 19ms |
| 健康检查（基线） | 5ms | 7ms |

### 规格边界

以上数字仅代表单机开发规格（Apple Silicon、本地 PostgreSQL/RabbitMQ/SeaweedFS），
**不外推生产容量**（DESIGN 21.3 写作限制）。生产规格需在目标环境重测。

## 6. 已知限制（项目收尾状态）

1. **生产部署**：全栈 compose 适合演示/小规模；生产需要 TLS/域名/独立数据库
   （DESIGN 20.1 记录为环境配置事项）。
2. **QA 对话模型**：未配置（本机无 LLM）；接入云端 Key 或本地推理（Ollama 等）
   后 QA 即刻可用（机制完整）。
3. **单格级索引/重排**：DESIGN 15.2 后续；当前页级定位满足验收。
4. **跨用户改编授权**：DESIGN 3.2 边界，未实现。
5. **e5 对中日文的长文本语义效果**：15 条小集定性可用；扩大标注集属后续事项。
6. **单格精排/重排模型**：DESIGN 15.5 边界，未实现。
7. **HLS/多码率**：DESIGN 14.2 不做。
8. **容量数字**：单机开发规格，不外推生产（21.3）。
