# 外部漫画与条漫按需加载验收

2026-11-12，Asia/Shanghai。变更：`lazy-load-external-manga-pages`。
设计依据：DESIGN §14.1、§19、§21。

## 各源能否复用 HTTP 方案

本轮核对的是 MangaShelf 当前实现，不把浏览器提取地址误称为截图，也不依据代码注释
断言某个上游永远无法纯 HTTP 解析。

| 来源 | 当前获取目录/章节清单的路径 | 本轮结果 |
| --- | --- | --- |
| 哔哩 | Java HTTP、匿名指纹和章节索引；原图持久缓存 | 保持既有同源读取、错误与缓存边界，回归真实末页 |
| 腾讯 | Java HTTP 及已有页图解码钩子 | 无需迁移成哔哩接口；真实章节末页通过 |
| MangaDex | Java HTTP API | 使用同一按需页组件；未新增真实上游样本验收 |
| 拷贝 | 榜单 HTTP；详情、章节由现有 Playwright 路径提取 URL | 阅读端按需取图；本轮未实现或声称纯 HTTP 清单提取 |
| 包子、嗨皮 | 当前规则为浏览器计划，提取页图 URL | 阅读端按需取图；完整清单的 HTTP 替代需分别验证脚本、分页和访问限制 |

“完整索引 → 阅读位置附近图片 → 缓存”的思路可以复用，但哔哩的参数、匿名指纹和令牌
不是通用上游协议。浏览器源冷解析期间，源站自身仍可能发出图片请求；本轮没有把服务端
解析浏览器改成禁止下载图片，也不声称这些来源已经完全脱离浏览器。

## 已实现行为

- 所有外部源共用 `ExternalMangaPage`。确认阅读进度前不赋正文地址，滚动只加载视口
  附近图片；翻页只挂当前组并预取下一组。完整页序保持占位。
- 不再额外预读章首两图判断条漫，用清单尺寸、本机尺寸或正在阅读的图识别。首次识别
  为条漫时保持所在页切入滚动；手动单双页优先，切换时保留所在页或包含该页的页组。
- 未知尺寸使用估计占位。实际尺寸到达前记录当前阅读锚点，更新布局后修正滚动。
  本机仅记录最近 20 个来源/章节、每章至多 1,000 个已测量尺寸，不保存 URL、正文、
  Cookie 或签名；尺寸只是布局提示，不是访问授权或下载成功证据。
- 普通 CDN 图片使用原生 img，保留浏览器 HTTP 缓存和原有白名单代理。直连失败只
  尝试一次既有代理，最终失败显示页级重试，不再隐藏图片。
- 哔哩保留同源 fetch、取消请求、JSON 错误与 `private, no-store`，服务器缓存策略不变。
  其他源的代理缓存沿用原实现，没有新增通用服务端图片缓存。

## 生产 Web 构建的受控验证

`scripts/serve-reader-validation.py` 只绑定本机回环地址，用真实 `web/dist`、
生成的 PNG 和临时内存进度提供验收页面。每章 80 页，长条图 800×3200 / 800×4800
交替，普通页 800×1200；章节清单大部分不提供尺寸。服务端记录真正收到的图片请求，
不只检查 DOM 是否带 `loading=lazy`。

通过 Codex 内置浏览器操作真实阅读器。以下是实际观测，范围会随窗口、预取以及估计
占位高度变化；不把某次请求数量固定成所有窗口都必须相同的性能承诺。

| 场景 | 结果 |
| --- | --- |
| 首次打开无尺寸条漫 | 80 个页位；首轮只请求第 1 页，识别条漫后保持第 1 页 |
| 直接跳第 80 页 | 同轮总请求仅第 1、80 页；第 80 页首次 502，显示页级失败；点击重试后 800×4800 完整解码 |
| 冷续读第 40 页 | 仅请求第 39–42 页，没有章首；当前页为 40，尺寸到达后第 40 页顶部仍在视口 top=0 |
| 使用已测尺寸刷新 | 恢复第 40 页，没有章首请求，阅读位置稳定 |
| 手动双页再回滚动 | 双页显示第 39、40 页，回滚动仍为第 40 页，top=0 |
| 双页偏好下首次识别条漫 | 先从第 40 页所在组恢复，识别后切滚动仍在第 40 页，未请求章首 |
| 站内点击下一话 | 新清单延迟期间只显示解析状态，不沿用上一话图片；下一话恢复第 40 页，仅请求第 39、40、41 页，均在该话进度响应后发起 |
| 普通页双页 | 显示第 39、40 页，服务器只收到第 39、40、41、42 页请求 |
| CDN 与代理均失败 | 用不同回环主机模拟跨域图片，第 80 页直连失败、代理失败，显示重试；点击后再次直连成功，代理没有无限重试 |
| 哔哩同源错误 | 第 80 页显示服务器 JSON 原因「受控图片失败，请重试」，重试成功并保持第 80 页 |
| 当前窄窗口 | 484×827，条漫无水平溢出；第 40/80 页完整显示，保存了界面截图 |

实测发现原生 img 在同地址重试时可能保留失败元素，状态停在加载中；已在重试时移除
旧图片元素，再重新赋地址。最终受控样本分别确认服务器收到两次末页直连请求，以及
跨域失败路径只发生一次代理请求。上述图片为生成样本，不代替真实上游可用性结论。
另将清单状态与来源、章节原子绑定，避免 SPA 切章期间短暂使用旧清单。修复后重新构建，
使用延迟清单和不同续读位置的相邻章节复验通过。

## 复现与限制

```bash
cd web && npm run build
cd ..
processing/.venv/bin/python scripts/serve-reader-validation.py
```

在本机浏览器访问
`http://localhost:15174/manga-ext/read/resume?mangaId=resume&source=copymanga`。
`resume` 从第 40 页开始；`strip` 首次从第 1 页开始；`normal` 用普通双页；
`paged` 验证双页偏好下的条漫识别；`remote` 验证跨域直连/代理失败；`bili` 验证同源
读取与 JSON 错误。第 80 页每个样本首次失败一次。`/__check` 只返回请求页号和临时
进度，不保存凭据或上游 URL。不同样本会共享该测试站点的页模式偏好，双页场景需先
在阅读器设置中选择双页。浏览器缓存命中时，图片不一定再次到达验收服务器。

未知尺寸仍会使未读部分的估计总高度变化；本轮保证已测场景中的当前页锚点，不声称
所有未读图片都有精确高度。未对各 CDN、所有章节、长期风控或并发进行穷尽验证。
HTTP 缓存遵循原站响应；本轮没有承诺所有外部图片都会持久缓存或离线可读。
