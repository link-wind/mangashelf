# M24 验证：漫画首页发现流

日期：2026-11-10（真实环境 + 浏览器实测）

## 实现

- 规则源 `rank.sections`：同一源多分区，可各自覆盖 `url/list/fields`；
  字段新增 `regex`（从 href 提取 id）。无 sections 的源降级为单分区「热门」。
- `GET /api/v1/manga-sources/{source}/sections?limit=` 聚合返回。
- `/manga` 重写：源切换 + 5s/6s 自动轮播 hero + 分区横向卡片行（前三名角标）
  + 本地漫画区块；源选择存 localStorage。

## 数据源（2026-11-10 实测）

腾讯动漫首页当天 A/B 撤掉了男生/女生/畅销榜，改为使用更稳定的
`/rank/index?type=...&style=items` HTML 片段接口：

| 分区 | 来源 | 条目 |
|---|---|---|
| 编辑推荐 | 首页 `ul.recommend-list` | 12 |
| 飙升榜 | `/rank/index?type=rise&style=items` | 6 |
| 畅销榜 | `type=pay` | 10 |
| 新作榜 | `type=new` | 10 |
| 真香榜 | `type=hot` | 10 |

总耗时约 1.0s（5 个分区，4 次抓取：推荐页 + 4 个榜单片段均不同 URL）。

## 验证

- `/sections`：五分区全部有数据；榜单条目带「更新到 N 话」。
- 浏览器（1280×720）：
  - hero 轮播显示封面模糊背景 + 竖封面 + 标题/作者/chips/开始阅读；
  - 五个分区横排，前三名蓝色角标；
  - 图片 49/50 加载成功（1 张懒加载未触发）；
  - 切换哔哩漫画 → 单分区「热门」正常降级；切回腾讯后选择持久化；
  - 点击飙升榜第 1 名 → `/manga-ext/650207?source=tencent`，详情 701 话正常。
- 本地漫画区块在页面底部，搜索/网格/分页保持原行为。
- 测试 15/15 通过（新增：href regex 提取、分区拆分/去重/页脚过滤）。

## 已知限制

- 推荐无「查看全部」独立页；分区横向滚动不自动加载更多（limit=12）。
- 腾讯分区顺序按规则；若上游调整 type 含义，需改规则行（不改代码）。
- MangaDex/哔哩仅有单分区，首页只显示一行「热门」。
