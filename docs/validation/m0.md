## 3. 对象存储选型（回应 DESIGN 24.1-3）⚠️ 有变更

实测过程与结论：

1. **MinIO 已从 Docker Hub 撤下官方镜像**（`minio/minio` → pull access denied）。
2. `quay.io` 经 Docker Desktop 内置代理稳定 401（宿主 curl 可达，判定为代理链路问题）；
   `quay.m.daocloud.io` / `docker.m.daocloud.io` 对 quay 前缀 403。
3. 开发存储改用 **SeaweedFS**（Docker Hub 可拉取）：master+volume+filer+s3 单进程，
   sigv4 预签名 PUT/GET、Range 206、桶首次 PUT 自动创建。
4. 踩坑记录（对后来者有用）：
   - PG18 镜像挂载点必须为 `/var/lib/postgresql`（不再是 `.../data`）。
   - SeaweedFS 4.50 起 IAM 改为独立服务，静态 `identities` 不再经 `-s3.config` 生效。
   - 3.x 的 s3.json 身份格式为 `identities[].credentials[]{accessKey, secretKey}`
     （proto JSON，大小写敏感；扁平 `access_key` 旧格式被静默忽略）。
   - master 仅绑定 IPv4，healthcheck 必须用 `127.0.0.1` 而非 `localhost`（::1 被拒）。
5. 生产对象存储在部署阶段按实际环境另行决策；"S3 兼容"不代替能力验证（DESIGN 6.2）。

## 4. 上传协议与签名行为 ✅

| 场景 | 结果 |
| --- | --- |
| 创建上传 → 服务端 Key（`users/<owner>/uploads/<id>/original`）→ 预签名 PUT | 200 |
| 同幂等键重放创建 | 返回同一 uploadId，不重复建资产 |
| 过期签名（TTL 5s，等待 7s 后 PUT） | 403 拒绝 |
| 篡改签名（Signature 换位 / X-Amz-Date 改旧） | 403 拒绝 |
| Range GET（`bytes=0-99`） | 206，恰好 100 字节 |
| complete 幂等（重复调用） | 返回同一 verify 任务，不重复创建 |

## 5. 全链路与任务闭环 ✅

`scripts/smoke-m0.sh`（全新重建后复跑亦通过）：

1. 创建上传 → 预签名 PUT → 幂等重放；
2. complete（202）→ Worker 租约领取 `content.verify` → 流式 SHA-256 → 资产 VERIFIED；
3. 结果事务链式派生 `content.process` → outbox → broker 确认派发 → Worker 执行；
4. 固定协议调用 Python `image.derive`（JSONL 进度入 job_events）→ 产物路径/类型/摘要校验 →
   上传 `jobs/<job-id>/attempt-<n>/…` → READER_IMAGE / THUMBNAIL 资产入库（VERIFIED）；
5. 预签名 GET 下载产物，摘要可核对。

任务事件样例：verify 阶段 emit 两条 progress + 一条 result，sequence 递增正确。

## 6. 注入实验 ✅

| 实验 | 方法 | 结果 |
| --- | --- | --- |
| 重复消息投递 | 对已 SUCCEEDED 任务经 RabbitMQ 管理 API 重投同一消息 ×3 | 全部被消费确认；attempt 保持 1、job_events 无新增，未重复执行 |

## 7. Python 处理协议 ✅

- stdout 仅 JSONL 进度；stderr 日志；`result.json` 含产物相对路径、ordinal、role、
  content_type、宽高、字节数、SHA-256（宽高字段为 Java 端补充，MangaWeaver book.json 缺失）。
- 路径越界（`../../etc/hosts`）→ exit 1 + FAILED 清单。
- stdout 非 JSONL 时 Java 侧判定协议违约并使任务失败（严格校验）。

## 8. 已知限制与 M1 必办

1. **演示 owner**：M0 以固定 UUID 代替用户体系（assets/upload_sessions/jobs.owner_id），
   M1 identity 落地时替换并回填外键约束。
2. **租约恢复扫描未实现**（M1）：Worker 崩溃后的过期租约重派发依赖人工重跑；
   M0 的 commitFailure/ack 策略避免无限重投。
3. **未预期异常确认丢弃**：消费者对未预期异常 ack 放弃消息（避免重投循环），
   任务状态以数据库为准；M1 引入重投上限与 DLQ 时调整。
4. **CORS 未配置**：浏览器直传（M1）前需给 SeaweedFS 配置 CORS；本轮以 curl 实测无预检需求。
5. **Spring AI 未引入**：M0/M1 不需要；M4 前按 2.0.x 与 Boot 4.1.x 兼容矩阵实测锁定。
6. 本机网络限制：quay.io/ghcr.io 不可达（Docker 401）、brew bottle 偶发断流（重试可过），
   依赖以 Maven Central / Docker Hub 为主。
