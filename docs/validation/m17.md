# M17 验证记录：漫画多数据源与热门榜元数据

> 日期：2026-11-09 · 变更：implement-manga-sources（已归档）
> 结论：漫画侧建成「数据源注册表 + 能力声明」架构，已接入哔哩漫画（热门榜元数据）
> 与 MangaDex（榜单/搜索/详情/阅读），漫画页可按源切换热门榜。

## 1. 架构

```
MangaSource (id / name / capabilities / rank / search / detail / pages)
   ├── BilibiliMangaSource   RANK
   └── MangaDexSource        RANK + SEARCH + DETAIL + READ
MangaSourceRegistry（Spring Bean 自动注册）
   └── /api/v1/manga-sources/{source}/...
```

**能力声明**是关键：源不支持的能力返回 409 `SOURCE_CAPABILITY_UNAVAILABLE` 并说明原因，
前端据此决定「站内可读」还是「跳原站」，不做静默降级。新增源只需实现接口并注册。

## 2. 接口实测

| 能力 | 哔哩漫画 | MangaDex |
| --- | --- | --- |
| RANK | ✅ HomeHot 匿名可用（碧蓝之海/航海王/间谍过家家…） | ✅ `order[followedCount]=desc`（Solo Leveling 等） |
| SEARCH | ❌ 需登录（实测 code=99）→ 409 | ✅ |
| DETAIL | ❌ 需登录 → 409 | ✅ |
| READ | ❌ → 409 | ✅ 托管章节 |

统一入口：`/manga-sources`、`/{source}/rank`、`/{source}/search`、`/{source}/manga/{id}`、
`/{source}/chapter/{id}/pages`。

## 3. 工程细节

- **哔哩封面降采样**：原图单张 3.2MB，URL 追加 `@480w.jpg` 后 71KB。
- **MangaDex 韧性**：实测上游对 Java 客户端偶发 `Remote host terminated the handshake`；
  实现 10 分钟 TTL 缓存 + 失败回退陈旧值 + 一次重试，榜单首请求失败后恢复稳定。
- **图片代理白名单扩展**：`*.hdslb.com`（哔哩）与 MangaDex 两个域名；磁盘缓存。
- 前端 `/manga` 顶部「热门漫画」：源切换 pill、排名角标、更新进度、`站外` 徽标
  （不可站内读的条目点击跳官方页）。

## 4. 已知限制

1. 哔哩漫画仅热门榜可用（详情/搜索需登录态），无反查、无章节、无阅读。
2. 榜单是编辑/关注排序，不是个性化推荐；无「最近热门趋势」。
3. MangaDex 标题多为英文/罗马字，中文标题覆盖有限。
4. 多源之间没有做实体去重（同一部作品在 B 站与 MangaDex 会各出现一次）。
5. 未做按源配置偏好（默认源、隐藏源）。
